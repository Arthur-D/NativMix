## #39 — Rotary trail (MIDI)

### Problem

Linear end-of-sweep desync is fixed (trailing CC flush). Continuous absolute rotary turns still feel like software trails the knob. Primary host cause: physical `_device_loop` idle `sleep(0.05)` delays reads and `flush_due`; only one MIDI message is drained per loop tick.

### Target behaviour

- Idle poll ≈ **10 ms** (same order as virtual-port loop).
- Each tick: drain **all** pending input messages, then throttle/flush as today.
- Keep `CcVolumeThrottler` at **20 ms** unless hardware retest still lags.
- Do not treat motor-fader feedback takeover as the default rotary fix.

### Out of scope for #39

- Device firmware / serial baud changes (Arduino USB path is separate; #39 is MIDI CC).

## #37 — Window / layout / Learn

### 37.1 Edit MIDI auto-grow

When **Edit MIDI Channel** turns on, ensure Learn/Mute/Delete (and crossfader Learn, once present) fit without the user hunting for a resize handle. Prefer growing height (and minimum height) when content needs it; do not shrink on edit-off below the user’s current size unless already handled by existing compact logic.

### 37.2 SizeGrip

`QSizeGrip` must sit on the **window’s bottom-right corner**, not mid-layout under the MIDI button row. Root cause: bottom bar then `root.addStretch(1)` leaves empty space *below* the grip. Fix by overlay positioning (`resizeEvent` / layout that keeps grip at the frame corner) while leaving MIDI buttons on the bottom content row.

### 37.3 Crossfader width clamp

Bar width stays `crossfader_bar_width(n, strip_w)` but must be **`min(that, available_host_width)`** so the bar never draws past the window. Centering under the strip host remains.

### 37.4 Compact + scroll vs window move

`MainWindow.mousePressEvent` → `startSystemMove` must **not** steal:

- Horizontal/vertical scrollbars of `_ch_scroll`
- Other scrollbars that are clearly chrome

Strip reorder handles stay inactive in compact (existing). Prefer keeping a usable resize affordance in compact (grip visible or equivalent) so “can’t resize” does not return.

### V3 — Visible Learn on crossfader

When Edit MIDI is on and crossfader is enabled (hybrid / midi_only), show a **Learn** control centered under the A/B track (same arm/cancel semantics as today’s right-click Learn). Right-click Learn/Clear may remain as a secondary path. Edit-off hides the button and cancels in-progress learn (existing gate).

## A/B side labels (channel names)

### Behaviour (agreed)

- **No channels** on that side → label text stays **`A`** / **`B`**.
- **One or more** → comma-separated **display names** (same fallback as strips / A/B menus: custom label → `MIDI N` / `CH N`).
- **Overflow** → elide with `…` (`QFontMetrics.elidedText` / equivalent) to the label’s available width.
- Multiple channels per side remain allowed; opposite side + USB control channel stay ineligible (unchanged).
- Right-click on the side label still opens the assignment menu.
- Refresh on assign/clear, rename, rebuild, profile apply (same cadence as `refresh_crossfader_ui` / side menu model).

### Example

| Side A assignment | Label A |
|-------------------|---------|
| (none) | `A` |
| default USB ch 0 | `CH 1` |
| renamed “Game” + “Voice” | `Game, Voice` (or elided) |

## Success criteria

1. Slow absolute rotary CC: UI/audio tracks without obvious trail; linear end sync still OK.  
2. Edit MIDI on → controls visible without mandatory manual resize.  
3. SizeGrip at window bottom-right; window resizable in normal (and reasonably in compact).  
4. Narrow window: crossfader does not overhang.  
5. Compact: dragging scrollbar does not start window move.  
6. Edit MIDI on: visible crossfader Learn works.  
7. A/B labels show `A`/`B` or comma-separated (elided) channel names as specified.
